SDD — integração Meta (Muse Code)

Status: confirmado pelo utilizador em 2026-10-12 (Etapa Zero, make-me-happy). 1. Resumo

O ai-taskbar passará a ter um cartão para a Meta, fornecedora dos modelos Muse (muse-wonder-*, muse-spark-*) servidos pelo CLI Muse Code (muse). O cartão mostra duas coisas reais, de duas fontes independentes:

  1. Quota da assinatura — janelas de 5 horas e semanal com percentual e resets_at, obtidas de POST https://api.meta.ai/muse-code/key com o token de device-code (dca:) que o muse login guarda. É a mesma leitura que o CLI faz para cunhar a sua chave de inferência; o ai-taskbar decodifica só os campos de assinatura e descarta a chave cunhada e qualquer dado de pagamento, sem os gravar em lado nenhum.
  2. Histórico local de tokens — hoje e últimos 7 dias por modelo, lido dos session.jsonl que o CLI persiste em ~/.local/share/muse/sessions/, pelo mesmo padrão dos scanners Claude/Codex/opencode já existentes.

Não há preço público (o catálogo local traz cost: null para todos os modelos e os logs não trazem valores de cobrança), por isso o cartão mostra tokens e percentuais de janela, nunca dólares. Contas pay-as-you-go sem assinatura ativa mostram o estado real ("sem assinatura"), nunca uma barra 0% inventada — mesma regra "no denominator, no bar" dos créditos do Codex e do cartão TypeSafe.

A decisão CLI vs API vs web, verificada nesta máquina e na referência pública do CodexBar (Apêndice B): não existe subcomando muse usage nem API pública de uso por chave (META_API_KEY e chaves de dashboard recebem 401 no endpoint de quota). A via suportada na prática é a combinação acima: API de assinatura com a credencial do CLI (read-only, sem prompts) + scanner local. A quota de time via web (dev.meta.ai) fica desenhada como fase 2 (§17).

3. Objetivos e não objetivos

3.1 Objetivos

  1. Novo fornecedor VendorId.meta, exibido como "Muse (Meta)".
  2. Janelas de assinatura (sessão + semanal) com percentual sanitizado e contagem regressiva de reset, quando a conta tem assinatura ativa.
  3. Histórico local de tokens hoje/7 dias por modelo via scanner, somando na CostWindow única e entrando no Analytics como tokens (sem USD).
  4. Autenticação read-only partilhada com o CLI: ler o token dca: do auth.json inline ou do Keychain, sem prompts, sem refresh, sem write-back (a regra dos providers Anthropic/OpenAI aplica-se por analogia direta).
  5. Configuração [meta] desativada por padrão, sem campos de chave de API.
  6. Golden tests da wire type do mint e das linhas do scanner (política de imutabilidade do repo).
  7. make validate verde e cobertura Core+Providers ≥ 90%.

3.2 Não objetivos

  • Executar o CLI (muse exec, muse login/logout/auth) a partir do app. Nada de inferência para "sondar" a conta: custaria tokens ao utilizador.
  • Guardar, loggar ou mostrar o token dca:, a chave cunhada pela resposta, email ou payment_method. A resposta é decodificada por allow-list (§8).
  • Inventar quota: PAYG sem assinatura, subs_usage ausente ou Keychain bloqueado mostram estado honesto, nunca percentuais fabricados.
  • Prompt interativo de Keychain (nem o fluxo Authorize do Anthropic) nesta fase: leitura prompt-free apenas; bloqueado → cartão degrada para o scanner com nota (§7.3).
  • Cookies de browser / quota de time dev.meta.ai (fase 2, §17).
  • Preço em dólares ou entrada na PricingTable enquanto a Meta não publicar preços (modelos entram como unpriced, §10).
  • Feed de status: não foi encontrada página oficial; não inventar URL.

7. Autenticação (credencial partilhada com o CLI, read-only)

Novo seam em AiTaskbarCore/Credentials/: MetaCredentialReader (protocolo MetaCredentialReading para testes), ao lado do KeychainCredentialReader existente, reutilizando KeychainPromptSuppressor. Não generalizar o fallback /usr/bin/security para aqui: esse truque só funciona porque o Claude Code CLI grava o item com essa ferramenta; o item da Meta é gravado pelo binário muse.

7.1 Ordem de resolução do token

  1. auth.json (authPath config → MUSE_AUTH_PATH → ~/.config/muse/auth.json): providers.meta.access_token não-vazio com prefixo dca: → usar esse. Token inline sem o prefixo → ignorar (não é device-code; daria 401) e registar diagnóstico sem o valor.
  2. Sem token inline (incl. mechanism: "oauth" ou ficheiro ausente): Keychain, serviço ai.meta.dev.credentials, conta meta; o payload é JSON — extrair só o access token e validar o prefixo dca:.
  3. Nada encontrado → estado "sem login" (§4.1), sem erro ruidoso.

META_API_KEY nunca é lida para quota (401 garantido e semântica errada).

7.2 Regras de Keychain (as da casa, sem exceção nova)

  • Leitura dentro de KeychainPromptSuppressor.withPromptsSuppressed e kSecUseAuthenticationUI = kSecUseAuthenticationUIFail.
  • -25308/-25293 = ACL-blocked (isACLBlockedStatus): degrada (§7.3), nunca prompt. Outros OSStatus propagam como erro.
  • Sem escritas: sem writeBack, sem refresh, sem rotação. O CLI é o dono do ciclo de vida; token expirado → 401 → mensagem "execute muse login".
  • Detetar "login existe?" (para Ajustes, §4.3) nunca pede o segredo: basta auth.json parseável nos termos acima ou presença do item por atributos.

7.3 Degradação

Keychain bloqueado/ausente ou mint indisponível não falha o cartão: o snapshot de quota fica stale (cache) ou ausente com nota localizada, e os tokens do scanner continuam visíveis. Se também não houver sessões, o cartão mostra o estado "sem login / sem sessões" com a ação muse login.

8. Provider de quota (MetaProvider + MetaWireTypes)

AiTaskbarProviders/MetaProvider.swift sobre CachedFetch (sem boilerplate novo) e HTTPClient partilhado (env.http, para pin_hosts o alcançar).

O único pedido que este provider pode construir:

POST https://api.meta.ai/muse-code/key
Authorization: Bearer <dca token>
x-api-version: 1.0.0
Content-Type: application/json
{}
  • Host fixo, HTTPS, sem redirects (resposta 3xx = indisponível). User-Agent é o do app — nunca disfarce de browser/CLI.
  • Cancelamento: try Task.checkCancellation() à entrada, depois da rede e antes de escrever a cache (regra da casa).
  • A cache guarda o MetaSnapshot interpretado, nunca token nem corpo bruto.

Decode por allow-list (MetaWireTypes.swift). Só estes campos existem para nós; a chave cunhada, payment_method, email e tudo o resto não são decodificados:

struct MetaMintResponse: Decodable {
    let isSubsActive: Bool?        // is_subs_active
    let requirePayment: Bool?      // require_payment
    let subsTierName: String?      // subs_tier_name
    let subsUsage: SubsUsage?      // subs_usage (ausente/null = idle, §2.2)
    struct SubsUsage: Decodable {
        let window: Window         // used_percent, resets_at, window_duration_mins
        let weekly: Window         // used_percent, resets_at
    }
}
  • used_percent: Double externo → UtilizationPercent.sanitized, clamp 0–100; NaN/infinito nunca chega à UI.
  • resets_at: segundos Unix; fora de (0, 64092211200] → data omitida, percentual mantido (nunca descartar a janela por causa da data).
  • window_duration_mins: via Int(checkedTruncating:); inválido/≤0 com janela presente = drift de formato → indisponível com stale, sem crash.
  • Mapeamento de estado: require_payment == true → .billingIncomplete; senão is_subs_active == true → .active; resto → .payAsYouGo.

Erros → AppError (casos exatos a fixar na task, seguindo os vizinhos): 401/403 = login expirado (mensagem com muse login); 429 = rate-limited (alimenta o backoff do RefreshScheduler); 5xx/transporte/drift = indisponível servindo stale; sem credencial = estado vazio (§7.3), não erro.

9. Scanner local de tokens (MuseSessionScanner)

AiTaskbarCore/Cost/MuseSessionScanner.swift, gémeo estrutural de ClaudeSessionScanner/CodexSessionScanner: enum stateless + ScanMemo partilhado, ficheiros memory-mapped, pré-filtro por bytes antes do decode.

  • Raiz: sessionsDir config → MUSE_SESSIONS_DIR → $XDG_DATA_HOME/muse/sessions → ~/.local/share/muse/sessions. Passeio YYYY/MM/DD/*/session.jsonl com pré-filtro por mtime, mas o bucket é pelo recorded_at (µs → Date) no calendário local: uma sessão pode escrever turnos depois da data da pasta. Janelas da CostWindow única (hoje = meia-noite local; 7 dias = hoje + 6 dias anteriores). Proibido cutoff próprio em segundos (regra AGENTS.md).
  • Linhas que contam: envelope {recorded_at, payload:{event:{kind, model, usage}}} com kind ∈ {model_completed, automated_review_completed}. Pré-filtro por bytes nesses dois literais. Ignorar: linha-cabeçalho do frame, resource_usage_sampled, goal_usage_attribution, record.quantity e qualquer outro kind — são rollups/telemetria e duplicariam (medido §2.1). Linhas com usage malformado são saltadas e contadas como drift parcial (nota no CostEstimate), nunca fatal.
  • Semântica dos tokens — não generalizar de outro scanner (tabela nova para o AGENTS.md):
input inclui cached?reasoning
MuseSessionScannersim — subtrai-se o cache readsubconjunto de output, não se soma

Mapeamento para ModelUsage (saturating, nunca negativo): cacheReadTokens = cache_read_tokens ?? cached_tokens; inputTokens = max(0, input_tokens − cacheReadTokens); cacheCreateTokens = cache_write_tokens; outputTokens = output_tokens (reasoning já dentro). Fixado por teste dourado com a série medida (§2.1): se um dia o CLI passar a reportar input sem cache, o teste falha em vez de inflacionar em silêncio.

  • Atribuição por modelo: event.model da própria linha (nunca um modelo "da sessão" — lição do opencode). Linha sem modelo → bucket "unknown", tokens mantidos.
  • Deduplicação: não foi observado replay da mesma resposta (ao contrário do Claude Code). Sem dedup especulativo: cada model_completed conta uma vez; se surgir evidência de reemissão, trata-se como bug novo com fixture.
  • Limites: os do padrão da casa (memo por ficheiro, saltar ficheiros fora da janela por mtime); scan parcial/corrompido devolve subtotais válidos + note. Dia sem leitura possível ≠ zero medido.
  • Paths ganha o resolvedor da raiz Muse; session-index.db não é lido (não tem tokens; ler SQLite de outro app é superfície sem benefício).
